- `Worker`, `WorkerVersion`, `SourceRef`, `TaskInstance`

- `EvaluationSpec`, `EvaluationResult`, `ExperimentSpec`, `ExperimentResult`

New types added:
- `SourceRef` — Git provenance (repository, commit, path, digest)
- `TrustTier` — CANONICAL_DOCTRINE, VALIDATED_FINDING, TRANSFER_CLAIM, WORKER_MEMORY, VENUE_INTEL, TASK_MATERIAL, EPHEMERAL
- `TransferClaim` — finding claimed to transfer across venues
- `PromotionReceipt` — evidence-linked promotion record
- `FindingTier.TRANSFER_REJECTED` — for rejected transfers

`compute_digest()` method on all FrozenModels for content verification.

### Phase 1: Canonical Append-Only Event Ledger (`lab/ledger/__init__.py`)

SQLite WAL with:
- Triggers rejecting UPDATE and DELETE
- Chain hashing (previous_event_hash links events)
- `append_event()` — add event with auto-hashing
- `get_event()`, `get_entity_history()`, `get_events_by_type()`
- `verify_event()` — check single event hash
- `verify_chain()` — check entire chain integrity
- `export_receipt()` / `import_receipt()` — idempotent cross-node transfer
- Conflict detection: same ID + different payload = HARD FAILURE

### Phase 2: Content-Addressed Artifact Store (`lab/artifacts/__init__.py`)

- `artifacts/sha256/ab/rest...` directory structure
- `store()`, `store_json()`, `store_text()` — store with digest receipt
- `retrieve()`, `retrieve_json()` — fetch by digest
- `verify()` — recompute hash, detect tampering
- `list_artifacts()`, `count()` — inventory
- Metadata sidecars (`.meta.json`) with provenance

### Phase 3: Hydra Projector (`lab/projection/__init__.py`)

- `HydraProjector` — reads ledger events, creates HydraDB graph nodes
- `rebuild()` — clear graph, reconstruct from all ledger events
- `verify()` — check graph matches ledger state
- Event dispatch table maps event types to projection methods
- Critical test: delete Hydra, rebuild from ledger, verify identical

### Phase 4: Real Execution Backend (`lab/execution/__init__.py`)

- `ExecutionBackend` Protocol — `execute(run_spec, budget, context) -> dict`
- `WorkerKitBackend` — Letta runtime (localhost:3000), stores artifacts + trajectory
- `DirectBackend` — testing, no external services
- Records execution events to ledger
- Returns artifact refs, trajectory ref, evaluation metadata

### HydraDB Schema Extended (`integrations/hydra/schema.py`)

Added node types:
- `create_world_genome()` — CGE world configurations
- `create_run_with_world()` — Run + WorldGenome linked
- `create_capability()` — per-worker capability evidence
- `create_failure_mode()` — failure pattern tracking
- `create_insight()` — experiment insights
