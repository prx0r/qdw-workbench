#### 3. HydraDB constraints discovered (critical for all future work)
- **Only** `CREATE (a)-[:EDGE]->(b)` works for writes (creates both nodes + edge)
- `MERGE`, standalone `CREATE`, `MATCH + CREATE` all FAIL
- Node `id` property MUST be integer (use `hash_id()`)
- `RETURN n.property` not `RETURN n`
- `count(*)` not `count(n)`
- MATCH requires label or property predicate
- Graph is immutable by design — updates = new nodes + edges (versioned lineage)

### Key architectural decisions
1. **One shared graph** — all studios (bittensor, metaculus, etc.) write to same HydraDB instance
2. **Studio isolation via node properties** — `Run {studio: "bittensor"}` not separate graphs
3. **Immutable graph** — every write creates new subgraph, updates = new nodes + edges
4. **Separate repos as modules** — workerkit, mwgym, oracle are domain adapters that plug into private-lab
5. **CG stays separate** — evolution kernel, plugs in via adapters
